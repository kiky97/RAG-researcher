# 毕业设计与求职准备

## 题目与研究目标

建议题目：**基于 DeepEval 的检索增强生成问答系统设计与质量评估**。

研究问题：分块长度、检索数量、检索多样性与提示词如何影响回答质量和延迟？重点是建立可追溯的实验与问题诊断流程，并明确统计代理指标与语义评估的差异。

## 系统结构

```text
浏览器（原生 HTML / CSS / JS）
    │ REST JSON、multipart 文件上传、进度轮询
FastAPI
    ├── 文档解析 → 字符分块 → TF-IDF → 余弦相似度 / MMR
    ├── 回答：离线原文抽取 / OpenAI 兼容模型接口
    ├── 评估：本地统计 / DeepEval + 自定义兼容模型适配器
    └── SQLite：文档、测试集、实验、资料快照、报告
```

新增模块与上游职责：`core.py` 负责应用的分块、检索与本地统计，`models.py` 负责模型接口及 DeepEval 适配，`main.py` 负责 API 与实验流程，`store.py` 负责持久化。DeepEval 负责语义评估算法。所有新增代码可独立阅读并验证。

## 实验方案（实际执行后再填结论）

演示的 8 条问题只用于功能验证。毕业实验建议自建一个明确领域的知识库和至少 50–100 条人工校验样本；把开发集和最终测试集分开，固定测试集，不用测试答案反复调参。

| 实验 | 固定条件 | 变量 |
|---|---|---|
| 分块实验 | 同模型、提示词、K、检索策略 | 200 / 360 / 600 字符 |
| 召回数量 | 同模型、分块、提示词 | Top K 1 / 3 / 5 |
| 检索策略 | 同模型、分块、K、提示词 | TF-IDF / MMR |
| 提示词实验 | 同模型和检索配置 | 默认 / 条件约束更明确的提示词 |

逐组只改变一个变量，保留导出 JSON。记录语义评分、来源召回、平均耗时、失败样例；模型实验建议重复运行三次并自行汇总均值与波动。平台当前不自动计算置信区间，也不自动记录 token 费用。人工盲评一部分样本，检查评审模型对漏答、引用错误和否定句的判断。

有效性威胁：示例小且简单、参考答案措辞影响 F1、词元覆盖率对抽取回答偏高、同模型生成与评审产生偏差、模型服务端版本可能变化。报告负向结果，不预设 MMR 必须优于基线。

## 五分钟演示流程

1. 载入演示资料，介绍其虚构性质与领域替换方式。
2. 提问「毕业答辩需要提交什么材料？」，展示回答和引用片段。
3. 创建 `baseline-k3`：TF-IDF，分块 360，K=3，本地评估。
4. 创建 `mmr-k3`：仅把检索策略改为 MMR，展示指标并排对比。
5. 打开未通过案例，解释参考答案、检索片段与实际回答的关系。
6. 导出报告，展示配置、文档哈希与原始资料快照。
7. 有真实模型配置时额外运行 LLM + DeepEval，并明确其费用和判断偏差。

- 文档变化、服务重启、模型超时会如何影响实验？
